## 專案是什麼

**正式名稱：人力銀行app**（規劃期間也稱「匯聘計畫」，指同一個專案）。這個 repo 原本只有材霈公司的 LINE 招募機器人「沛沛」（單一雇主、Notion 職缺庫），這個新專案是完全獨立的規劃，目標是做一個綜合小雞上工／Worky／GoGoJob 定位的求職平台。

## 業務背景與範圍演進（重要，決定了為什麼 V1 長這樣）

規劃一開始設想的是「開放式雙邊市集」（多雇主自助刊登），但討論過程中確認了幾個關鍵事實，範圍因此大幅調整：

1. **使用者本身經營一家派遣公司**，目前每月有 6,000-8,000 筆履歷流量，會盡力導入新平台——這是**保證會發生的真實流量**，不是要驗證有沒有人用
2. 這些履歷**主要是應徵自己派遣公司承接的職缺**（B2B，雇主端其實是內部派案窗口），不是流向多個外部客戶雇主
3. 因此 **V1 範圍改成「內部化」**：把現有派遣流程系統化，不做開放式多雇主市集——這個決定大幅縮小了 V1 的工程範圍（不需要多租戶自助刊登、金流、公開評價系統）
4. **長期展望不只是內部使用**：明確目標是之後開放外部商家自助刊登、對外收費，做成像小雞上工那樣的平台，之後也計畫做越南版本——所以資料模型（`Client.mode` = MANAGED/SELF_SERVE 雙軌）跟通訊管道都刻意設計成可擴充，不是只服務 V1

## 團隊與協作模式（這點會直接影響怎麼做決策）

- 開發團隊只有：使用者本人 + 最多一位助理 + Claude（AI 協作）
- **內部同仁完全沒有程式背景**，包含使用者自己——所有程式碼都是「Claude 提供，他們使用」，沒有人能獨立審查程式碼品質或抓資安漏洞
- 時間投入是**業餘時間**（晚上/週末，約每週 8-15 小時），不是全職
- 曾討論過「跟 Claude 協作 vs 發包外部工程師」，結論是**維持跟 Claude 協作為主線**（理由：這個 repo 本身的 `HANDOFF.md` 就是活生生的成功案例；而且「沒有人能審查」這個問題不管選哪邊都存在，換發包也解決不了）
- **重要待辦、還沒真的去找**：建議找一位獨立技術顧問/資安顧問，用定期審核的方式把關（不用全職），這是目前規劃裡唯一建議花錢外包的技術性工作，優先度很高，尤其是上線收費/處理真實金流之前

## 外部依賴：既有履歷系統

候選人履歷目前是透過一個外部工程師開發的系統在收，網址範例：`https://resume.tsaipei.com.tw/...`（base64 參數含 `UserNo`/`ResumeKind`/`System`），`config.py` 裡的 `DEFAULT_RESUME_URLS` 就是這個系統的入口。`HANDOFF.md` 裡记录過一個尚未解決的舊待辦：填完履歷不會自動導回 LINE，需要跟這位外部工程師協調。

**現況**：使用者已經跟這位外部工程師談好，會開放資料存取管道（採用「同步」而非「取代」的方案 A）。**還沒確認的技術細節**（下次接手時要優先跟催）：
1. 存取方式是唯讀資料庫連線、REST API、還是排程匯出檔案
2. 有沒有唯一識別碼可判斷「是否已同步過」
3. 有沒有更新時間戳記可做增量同步
4. 完整欄位清單
5. 存取權限是唯讀還是可寫、有無頻率限制
6. 每筆應徵記錄有沒有標記對應哪張職缺單/客戶（這點目前推測沒有，需要人工分派）

## 內部組織結構（已確認，資料模型已對應）

- 約 40 個內部帳號，角色分「總管理者」（跨團隊）／「主管」（管團隊）／「專員」（處理被指派的應徵者）
- 5 個團隊，**依客戶劃分**，但同一客戶可能同時有多個團隊服務（多對多關係）
- 對應到 `Team`/`Client`/`TeamClientLink`/`StaffUser` 這幾張表，細節見 `job-app-data-model.md`

## 其他已經討論過、還沒寫進正式文件的建議

- **法遵風險（優先度高，建議儘早確認）**：在台灣做「跟外部雇主收費的求職媒合平台」，很可能需要私立就業服務機構許可，且對向求職者收費有嚴格限制——這件事建議直接問配合的律師/會計師，不要等工程做完才發現卡在這關
- **資料庫託管建議**：Cloud SQL for PostgreSQL，跟現有 repo 同一個 GCP 專案（`tsaipei-505807`）、同地區（`asia-east1`）。關鍵設定：不要開放公開 IP（僅限私有網路連線）、密碼放 Secret Manager、開自動備份+時間點還原、真正上線收費前要開高可用性(HA)
- **On-call 是唯一沒有純技術解法的風險**：兩人團隊沒有備援，建議之後抓預算找 part-time 待命合約，而不是假設兩人能撐住所有時段
